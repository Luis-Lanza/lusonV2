# Unified reconciliation modal

## Delivery boundary

This unit supplies the modal and its styles without mounting it in the transfer
screen or changing the existing detail table. The component, stylesheet and tests
are exact copies of their main-worktree sources. Caller activation is a separate
unit; this delivery does not remove historical evidence or legacy controls.

## Review before mutation

For each expected variant, either endpoint can propose actual dispatch, arrival
and physical retention quantities with a reason. Origin alone attests positive
retention. Partial retention and overdispatch are supported by the established
view/model contract; overdispatch cannot be combined with retention.

Review shows the expected workflow revision, reason, quantities, unresolved
origin/transit differences and uncredited excess. Proposal effects are hypothetical;
rejection shows zero stock effects. Only explicit confirmation invokes the hook's
mutation command. Opening, editing, reviewing and closing do not submit writes.
Acceptance delegates atomic application to the existing API contract, not a chain
of legacy commands. Unknown quantities are not automatically classified as losses.

## Focus and recovery

The optional stable entry trigger and native modal focus binding preserve the
caller's opener. The dialog isolates background content, contains keyboard focus,
and supports Escape, backdrop and explicit close controls. Authority changes mask
the dialog; a refreshed record retires the opening.

Uncertain operations retain their exact payload and operation key. Recovery is an
explicit read; retry is a separate explicit action using the same operation.
No local stock application or automatic POST is performed by an effect.
