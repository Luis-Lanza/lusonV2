# Safe administrative deletion
Implement admin-only logical deletion of personal users and branches, preserving historical evidence.
Base: `d844795`; local work-unit commits on `feat/admin-soft-delete`; no push, PR, merge or physical purge.

## Specs
S1. User request, verbatim: “okey! ahora falta un lugar donde se puedan eliminar sucursales y eliminar usuarios. todo esto desde el admin”. Add account and branch deletion actions to the existing Administration surface, keeping the sole warehouse and its administrator protected.
S2. User clarification, verbatim: “okey pero si se elimina solo se podria acceder desde el serviodor no? la persona ya no la veria en la UI”. Accepted safe-deletion semantics: deleted users cannot log in and existing sessions lose authority; deleted users disappear from the normal admin directory. Deleted branches disappear from operational selectors and cannot be used for new operations. Retain underlying records and historical names/actor snapshots; do not erase or manufacture history.
S3. User approval, verbatim: “okey! entonces hagamos eso”. The accepted recommendation distinguishes temporary deactivation/reactivation from deletion and blocks branch deletion while stock/reservations, assigned nondeleted users (including disabled users), or unresolved operations remain. Include received transfers with pending count/restitution/reconciliation work, not only pending transfer headers. Do not add a deleted-record UI, restore flow, server recovery command, physical purge, anonymization or name/ID recycling.
S4. Standing user constraint, verbatim: “cada uno tendra usuarios! y solo habra una cuenta de almacen! nada mas! esa cuenta es el admin y no se puede crear nuevos almacenes de momento asi es el negocio”. Preserve existing authority and business contracts: admin-only mutation, Origin/CSRF guards, personal assignment, complete active branch operations, immutable history, existing bootstrap/realtime completeness matrices, username/ID uniqueness and strict response shapes. Confirm destructive-intent actions and preserve existing private-owner/uncertain-outcome handling. New migrations only; never rewrite historical migrations or auto-delete records in the running preview.
